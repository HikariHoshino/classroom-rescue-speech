## 二、设计思路

### 2.1 为什么是「Python 引擎 + TS 适配层」两层

文档要求后端是 Node/Express，但团队批准用 Python 写 AI 部分。折中方案：

```
浏览器 → Express :3001 → server/ai/index.ts（TS 适配层）→ 127.0.0.1:8000（Python 引擎）→ 大模型
```

- **Express 侧只做**：字段校验、超时控制、结果兜底、错误码映射——保证公共契约（`shared/types.ts`）一个字不改；
- **Python 侧负责**：提示词、模型调用、结果校验、原文整理——这部分改动频繁，独立可测（27 个用例），不会牵连前端；
- 浏览器永远不直连引擎，**密钥只留在后端**。

### 2.2 为什么 Python 零第三方依赖

演示电脑上 `python` 是 Conda 3.9，没有 fastapi/httpx；装包要联网、要改 site-packages，现场一断网就废。所以引擎只用 `http.server` + `urllib.request` + `json`，**任何 Python 3.8+ 直接跑**，`python server/ai/engine/server.py` 一条命令启动。后续想换 FastAPI，只换 `server.py` 一个文件。

### 2.3 三级降级：演示不能黑屏

| 级别 | 触发条件 | 结果 | `resultMode` |
| --- | --- | --- | --- |
| 1 | 引擎在线 + 模型正常 | 模型生成 | `ai` |
| 2 | 模型超时 / 不可用 / 返回非法 JSON | Python 内原文整理 | `extract` |
| 3 | 引擎没启动 / 端口不通 | TS 本地原文整理 | `extract` |
| — | 完全没有文字 | 400 `no_transcript` | — |

第 3 级是特意用 TS 重写一遍原文整理换来的——演示当天 Python 没装、进程被杀、端口被占，主流程都不会断。这条路径实测过（杀掉 Python 后仍返回 200）。

### 2.4 为什么窗口由 1号 截取、3号 还要再校验一遍

文档要求「窗口和上下文由 1号 截取，3号 再次校验」。适配层会重做一遍归一化：**相同 id 覆盖更新、按 `startMs` 排序、剔除空文本、`endMs` 不小于 `startMs`**。这样即使上游截取有偏差，下游行为仍然确定，也不会出现重复片段。

### 2.5 为什么「疑似考点」不让模型写

实测 glm-4-flash 会把没有关键词的句子标成考点。现在**这一节由本地关键词函数生成后注入 Markdown**，模型只负责课堂主题和知识要点。好处：可复现、不编造、与前端雷达使用同一套规则。

### 2.6 为什么考点库离线、且用 408 真题

- **离线**：点急救要立刻出结果，实时联网搜索 2~5 秒一次，断网即废；985/211 期末题库也没有合法公开的批量来源；
- **408 统考**：国家统一命题、公开、可核查，每道题能指到「年份 + 题号」，比二手回忆版可靠；
- 星级只表达「这个知识点在历年真题里出现得多不多」，**不预测今年考不考**，界面统一写「疑似考点 · 参考频次」。

## 三、实现方法

### 3.1 回溯链路

1. 适配层校验：`sessionId` 非空、`fromMs ≤ toMs`、片段数组归一化；空文本 → 400；
2. 转发 Python：窗口最多取 12 段、每段 120 字，上下文最多 3 段、每段 80 字（控制输入长度 → 控制延迟）；
3. 提示词约束：**只能依据给定文字**、禁止逐字复制、三项合计 ≤110 字、`topic` 必须是 10 字内名词短语、信息不足写「现有转写不足以判断」、转写内容里的指令一律不执行（防注入）；
4. 结果校验：三个字段必须是非空字符串，`evidenceIds` **只允许引用本次请求里的片段 id**，越界直接丢弃；
5. 任何一步失败 → 原文整理，仍返回 200。

### 3.2 笔记链路

1. 模型只写「课堂主题 / 知识要点（≤6 条）/ 待确认内容」，合计 ≤260 字；
2. 本地关键词函数生成「疑似考点（原文）」小节并插入；
3. 收尾补齐：模型漏标题补 `# 课堂笔记`、漏「待确认内容」补默认说明。

### 3.3 分节链路（供笔记本）

`POST /api/notes/sections`：

1. 逐段用 `kb/match.py` 匹配到最接近的 408 知识点（别名加权打分，`分数 = 别名长度^1.5 × 出现次数`）；
2. **同一知识点的片段合并成一节**（不按位置切断），按星级降序、其次按时间排序；
3. 输出 `NoteSection`：`id / title / points / startMs / segmentIds / examStars / examBasis`；
4. 规则实现，所以 `resultMode` 老实标 `extract`——它是原文归类，不是模型总结。

### 3.4 考点权重库

统计流程（`build_weights.py`）：

1. 408 真题 PDF → `pdftotext` 转文本（18 份，2009–2026，约 23.9 万字）；
2. 按题号正则切分（1–47 题），剔除页码页眉噪声；
3. 每个知识点维护别名表，按「别名长度^1.5 × 出现次数」打分，取最高分且 ≥2.0 者归类；
4. 统计覆盖年份与命中题数；
5. 星级分档：**覆盖 ≥12 年 ★★★、6–11 年 ★★、1–5 年 ★**，未收录不标；
6. 每个知识点保留最多 3 条样例（年份 + 题号 + 原文片段），便于核查。

当前统计结果：

| 知识点 | 星级 | 覆盖年份 | 命中题数 |
| --- | --- | --- | --- |
| 树与二叉树 | ★★★ | 18 | 55 |
| 排序 | ★★★ | 18 | 40 |
| 图 | ★★★ | 18 | 37 |
| 查找 | ★★★ | 16 | 30 |
| 队列 | ★★★ | 13 | 24 |
| 栈 | ★★ | 11 | 11 |
| 线性表 | ★★ | 10 | 17 |
| 串与模式匹配 | ★★ | 7 | 8 |

### 3.5 考点雷达（前端纯函数）

- 词表：`这个要考 / 期末 / 考试 / 注意 / 重点 / 必考`，按顺序取第一个命中；
- **否定窗口 ±6 字**：命中词附近出现「不会考 / 不考 / 不是重点 / 无需注意」则不标星。不用「整段含否定词就跳过」，否则「这道题不考，但栈的判满是重点」会整段丢标；
- 每个片段最多一条，避免一张卡片被多个词刷屏；
- 同一套规则在 `src/radar/index.ts`、`server/ai/engine/keywords.py`、`server/ai/extract.ts` 三处保持一致。

## 四、实测数据

在演示机（Windows，Clash TUN，模型 glm-4-flash）上，完整链路 Express → Python → 智谱：

| 场景 | 耗时 | 模式 |
| --- | --- | --- |
| `/api/rescue`（10 段转写） | 7.0 – 9.4 秒 | `ai` |
| `/api/notes`（10 段转写） | 12.6 – 16.3 秒 | `ai` |
| `/api/notes/sections` | < 20 毫秒 | `extract` |
| 杀掉 Python 后的 `/api/rescue` | 3 毫秒 | `extract`（本地兜底） |

回溯样例（真实返回）：

```json
{"sessionId":"class-001","resultMode":"ai","data":{
  "missed":"老师讲解了栈的定义、特点、操作和顺序栈的实现方法，包括栈顶指针 top 的使用和栈空栈满的判断条件。",
  "topic":"栈和队列",
  "latest":"正在讲解栈在表达式求值中的应用。",
  "evidenceIds":["seg-02","seg-03","seg-04"]}}
```

延迟构成（`max_tokens=10` 空跑 5.4 秒，输出越多越慢）说明这里**瓶颈是模型出字速度，不是网络**，所以采取了「压缩输出 + 截断输入 + `max_tokens` 上限」三件套。

## 六、已知限制

1. **延迟偏高**：`glm-4-flash` 空跑约 5 秒，回溯 7~9 秒、笔记 12~16 秒。要更快只能换付费模型或降低输出长度；`LLM_TIMEOUT_NOTES_SEC=19` 已为笔记单独放宽，前端 20 秒超时是够的但余量不大。
2. **`topic` 有时偏宽**（例如给"栈和队列"而不是"顺序栈"），不影响主流程。
3. **分节是规则版**：按知识点合并，不做语义切分；同一段话提到两个知识点时只归一个。
4. **语料是考研 408**，不完全等同各校校内期末，星级只作参考。
5. **未做多轮对话**：每次回溯独立请求，不带历史。

## 八、安全说明

- `.env` 只在本地，已被 `.gitignore` 忽略，仓库中不含任何真实密钥；
- 密钥曾在协作沟通中出现，**建议演示结束后在平台控制台重置一次**；
- 引擎只监听 `127.0.0.1`，错误响应不返回密钥、不返回堆栈；
- 提示词中明确把课堂转写当**数据**处理，其中出现的任何指令都不执行。
